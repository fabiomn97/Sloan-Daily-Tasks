I got tired of not finding things.

Seven courses, each organized thoughtfully in its own way. The trouble only shows up when you're taking all of them at once. So I built the email I kept wishing existed.

Seven good systems, one tired student

Canvas isn't the problem, and neither are my professors. Each course is deliberately organized, and from the inside every one of them makes sense.

One course puts readings in Assignments, which gathers everything you owe into a single list. Another keeps them in Files, grouped by week, which is exactly what you want when you're revising for an exam. A third posts time-sensitive material as announcements, so it arrives rather than waiting to be found. Several keep the authoritative schedule in the syllabus, where it's complete and stable all term.

Every one of those is a reasonable answer to a real question. They just aren't the same answer. And the cost doesn't land on any single course, which is why no single course can fix it. It lands on the student holding all seven, opening a handful of tabs per class to answer one question: what do I actually need to do before tomorrow?

What I built

One email. 7:00am. Everything due and everything to read for the next seven days, in one place.

How it actually works

Two sources, because neither one is sufficient alone.

The syllabi give it structure. A PDF syllabus is the only place that says this reading belongs to Thursday's session. Canvas has no concept of that relationship. I parsed all seven into a single schedule file: 142 sessions, 42 deadlines, every reading attached to the class it's for.

Canvas gives it truth. A syllabus is written before the semester starts, and good teaching means adjusting as it goes. Canvas knows what moved, what got added, and what I've already submitted.

So Canvas always wins. But when it disagrees with the syllabus, the digest says so instead of quietly picking a side.

A deadline Canvas has that the syllabus doesn't gets tagged "not on the syllabus." One that moved gets tagged "syllabus said 18 Sep." I'd rather see the conflict than trust a merge I can't inspect.

Three decisions that mattered

Ask Canvas, don't guess

Some courses file readings under Assignments, so matching on titles was never going to hold. Instead the tool reads each item's submission type. Does Canvas actually expect a file back? If not, it's a reading, whatever it's called. One rule, nine courses, no maintenance.

Zero dependencies

Standard library only. Nothing to install, nothing to update, nothing that breaks in March because a package moved on. The whole thing is one file, one config, one scheduled task.

Keep the credentials local

The Canvas token has full account permissions, so it never leaves my machine. It sits in a gitignored config file that the script reads directly. The example config ships with placeholders.

Show submitted work anyway

Version one hid anything I'd turned in. It made the digest look wrong. Submitted items now stay put, greyed out and tagged, so "done" and "doesn't exist" stop looking identical.

What broke along the way

It crashed on its own output

Python on Windows defaults to a legacy character encoding that can't write an em-dash. My syllabus data is full of them. The file write died halfway and left an empty HTML file with no error I could see. Every read and write is explicitly UTF-8 now.

Hiding finished work made it untrustworthy

I thought filtering out submitted assignments would reduce noise. It did the opposite: I couldn't tell whether something was done or whether the tool had simply missed it. A digest you have to double-check isn't saving you anything.

A deadline hid inside a description

Restructuring the layout surfaced a planning document that was sitting in a class's prep notes rather than the deliverables list. It was due that same day. The bug was in my data, not my code, which is the kind you only find by looking at real output.

Ten is the limit

Canvas caps context codes at ten per request. With nine courses I was one under it and would never have noticed. Anyone taking eleven would have silently lost announcements with no error at all.

Where it goes next

  • Announcement triage. A single announcement often carries logistics and a genuine deadline change in the same paragraph. Surfacing the actionable sentence is the obvious next step.
  • Syllabus parsing that isn't me. I built the schedule file by hand from seven PDFs. Doing that automatically is what makes this usable by anyone other than me.
  • A weekly view. Daily is right for triage, wrong for planning. Sunday evening wants a different shape.
