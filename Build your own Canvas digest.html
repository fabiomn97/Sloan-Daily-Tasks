Build your own Canvas digest.

One email every morning with everything due and everything to read for the next seven days. You don't need to know how to code. You do need about ninety minutes.

What you'll end up with

An email that arrives at 7:00am, built from your own Canvas account and your own syllabi.

It groups the next seven days by date. Inside each day it separates what you have to hand in from what you have to have read, colour-coded so you can triage it before coffee. Work you've already submitted stays visible but greyed out, so "done" never looks like "missing."

Before you start

Check these three things first. The first one is the dealbreaker, and it takes thirty seconds.

  • Can you generate a Canvas access token? Go to your Canvas settings, scroll to Approved Integrations, and look for a "+ New Access Token" button. Some universities have disabled this for students. If it's missing, nothing else here works.
  • Do you have a Gmail account with 2-Step Verification on? You'll need it to generate an app password, which is what lets a script send mail. School Google accounts often block this, so a personal Gmail is safer.
  • Do you have your syllabi as PDFs? All of them. This is where the readings-per-session data comes from, and Canvas genuinely does not have it.

You'll also need Python installed. Claude will walk you through it if you don't have it.

Never paste a token or password into a chat

Your Canvas token carries your full account permissions — submitting work as you, reading your grades, seeing classmates' data in group contexts. Claude cannot reach Canvas anyway; the script runs on your machine and reads the token from a local file. Credentials go in that file and nowhere else. If you paste one by accident, revoke it immediately and generate a new one.

The four stages

So you know the shape of it before you start. Everything begins with one message.

  1. Send the prompt, syllabi attached · 2 min

    Copy the prompt below into a new Claude conversation and attach every syllabus in that same message. Both together, one message. Claude reads the PDFs directly.

  2. Claude interviews you, then builds your schedule · 25 min

    Which courses, which sections, which operating system, what time you want the email. Sections matter more than you'd think: get one wrong and the meeting days are wrong all semester. Then every session and reading from your syllabi becomes one editable file.

  3. You set up credentials and test · 30 min

    Canvas token, Gmail app password, a config file on your machine. Then three checks: do the courses match, does a digest build, does an email arrive.

  4. You schedule it, then tune it · 20 min

    A daily task at 7:00am. Then a week of small corrections as you spot things filed in the wrong place. This part never fully ends, and that's fine.

The prompt

Copy this into a new Claude conversation. Attach your syllabi in the same message.

It carries the full architecture, the bugs worth avoiding, and instructions on how to teach you — one step at a time, waiting for you at each stage rather than dumping thirty commands at once.

Paste into a new Claude chat 
I want to build an automated daily email digest that reads my university's
Canvas account, so I stop missing readings and deadlines. I am attaching my
course syllabi.

=== THE PROBLEM ===

Every professor organises Canvas differently. Some file readings under
Assignments, some under Files, some post them as announcements. The
authoritative schedule usually lives in a syllabus PDF that Canvas has never
seen. Each system is sensible on its own. The cost lands on the student
taking all of them at once, opening five tabs per course to answer one
question: what do I actually need to do before tomorrow?

=== WHAT I WANT ===

One email each morning covering the next 7 days. Grouped by day. Inside each
day, split into deliverables and class/readings. Colour-coded with a legend:
blue for readings, red for deliverables, green for class and prep.

=== INTERVIEW ME FIRST. DO NOT WRITE CODE UNTIL I HAVE ANSWERED. ===

Courses and sections, ask these one at a time:
- Which courses am I taking this semester?
- For EACH course, which section or cohort am I in? Syllabi list all of them
  (A-F, or ocean names like Mediterranean, or numbered like E2). Meeting days
  and rooms differ by section. Ask course by course. Do not assume one
  section applies to all of them.
- Are any of my courses NOT covered by the syllabi I uploaded?
- Are any uploaded syllabi for courses I am NOT taking? Drop those.
- Should Friday recitations and optional sessions appear in the digest?
- Do any of my courses split work by last-name initial (A-L vs M-Z)?

Setup questions:
- My operating system, and how comfortable I am in a terminal
- My Canvas web address, and whether my school still lets students generate
  access tokens
- What time I want the email and where to send it

=== ARCHITECTURE ===

Two sources merged, with Canvas authoritative:

1. A schedule file built from my syllabi. Only a syllabus says which reading
   belongs to which class session. Canvas has no concept of that
   relationship, which is why the syllabi are not optional.
2. The Canvas REST API, for announcements, live due dates, submission status,
   and anything the syllabus did not predict.

Where the two disagree, Canvas wins, but the digest must FLAG the difference
rather than silently picking one. Tag a deadline Canvas has but the syllabus
does not as "not on the syllabus". Tag one that moved as "syllabus said
18 Sep". I want to see the conflict, not trust a merge I cannot inspect.

Keep the schedule in one JSON file with courses, sessions and deadlines, so I
can fix a section, add a course, or correct a reading without touching code.

=== CONSTRAINTS ===

- Python, standard library only. No pip installs, no virtual environment.
- Runs locally on my own machine on a daily schedule.
- Sends via Gmail SMTP using an app password.
- Credentials live in a local gitignored config file and nowhere else.
- The email must render correctly in Gmail, which rules out most modern CSS.
  Use tables and inline styles.

=== BUGS A PREVIOUS BUILD HIT. PLEASE AVOID THESE. ===

- Classify readings vs deliverables by reading each Canvas item's
  submission_types and grading_type. Does it actually accept a handin? If
  not, it is a reading whatever its title says. Matching on titles is
  fragile and breaks differently in every course.
- Do NOT hide assignments I have already submitted. Grey them out and tag
  them. Hiding them makes "done" and "doesn't exist" look identical, which
  makes the whole digest untrustworthy.
- Canvas caps context_codes at 10 per request. Chunk them, or announcements
  silently disappear with no error.
- Force UTF-8 on every file read and write. On Windows the default encoding
  cannot write an em-dash and the script dies halfway through a file.
- Do not use %-d or %-I in strftime. They do not exist on Windows.
- Build inspectable commands: --check to show which Canvas courses matched
  which syllabus, --dry-run to build without sending, --audit to list every
  assignment and how it was classified. Do not ship a black box.

=== HOW TO TEACH ME THIS ===

Assume I have never used a terminal. I am not stupid, I am just new to it.

- Give me ONE stage at a time. Stop and wait for me to confirm it worked
  before moving to the next. Never dump the whole setup at once.
- One command per code block. Never more than about five blocks in a message.
- After each command, tell me what I should see if it worked, and what the
  most likely failure looks like.
- Use the exact syntax for MY operating system. Ask first if unsure. Do not
  give me macOS commands if I am on Windows.
- Explain any unfamiliar term the first time you use it, in one clause.
- When something errors, ask me to paste the error exactly rather than
  describing it.
- Never ask me to paste a token or password into this chat. If I do it by
  accident, tell me to revoke it immediately.
- Before each stage, tell me roughly how long it will take.
- Give me a way to verify each stage before we move on.

Start by interviewing me.

Attach every syllabus to this same message, before you send it. That is stage one, and there is nothing to do beforehand.

What to expect

It will not be right on the first run. Something will land in the wrong colour, a reading will show as a deliverable, a course will match the wrong syllabus. That's normal. Use --audit to see how everything got classified, and tell Claude what's wrong.

Your syllabi will contradict themselves. An assignment described as due one date in the text and another in the summary table. Claude should flag these rather than silently choosing, and Canvas settles it either way.

Budget a week of small fixes. The first few mornings you'll spot things. After that it mostly runs itself until a token expires.
